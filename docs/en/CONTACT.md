# Contact: reference and manual setup — rc.12

[English](CONTACT.md) · [Português](../CONTACT.md)

Balaio includes only an editable [Contact content reference](../../examples/pages/contact.en.html). **The theme does not create the page, install a contact form or activate widgets by URL.** The blog administrator creates the page and configures the contact method and any form.

## Create your page

1. Under **Blogger → Pages → New page**, create Contact. Reuse an existing page if available.
2. In HTML view, copy the body of [contact.en.html](../../examples/pages/contact.en.html) or [contact.pt-BR.html](../../examples/pages/contact.pt-BR.html). Replace its guidance text with your actual contact channels. The theme supplies H1.
3. Publish and **copy the actual URL generated by Blogger**. Do not infer it from the title: it can include a suffix such as `/p/contact_1234567890.html`. This is a valid address; there is no need to recreate the page to obtain `/p/contact.html`.
4. Use the actual URL in **Pages/Menu** when configuring links manually. Existing automatic navigation also uses published-page feed URLs, including suffixes. [Menu modes](PAGES.md).
5. Open the public URL and check content/links on a phone. XML does not publish or change the page content.

[Blogger’s page instructions](https://support.google.com/blogger/answer/165955?hl=en).

## If you want a form

Configure it separately with your chosen service or feature. Set the recipient, fields, appearance and placement, then confirm actual delivery. This repository’s content reference contains no form or send button.

Blogger offers a **Contact Form** gadget. It needs the platform’s native JavaScript/session data; copying form HTML into a page does not configure delivery. This theme does not reserve a visible area for that gadget: installation and placement require manual Layout/XML configuration. Its legacy sidebar is hidden; adding a gadget there does not make it visible. [Blogger gadget guidance](https://support.google.com/blogger/answer/176245?hl=en) · [Contact-widget requirements](https://support.google.com/blogger/thread/252064400/how-to-edit-contact-form-gadget-texts?hl=en).

If you want visitors to send without signing in, verify that behavior in your configured form. Explain what data is sent, who receives it and which service processes it. The privacy page should reflect the blog’s actual setup; the included sample remains a placeholder.

## Upgrading from rc.11

rc.11 attempted to match ContactForm1 to two fixed paths. That integration is removed in rc.12. Import the updated XML. If Blogger retains the **Contact form / ContactForm1** gadget created by rc.11, remove it in Layout; retain the page and any independently configured form.

Edit the page content in the dashboard too: remove wording such as “form below” if no form is configured. Importing XML does not replace published text.

Original code and the text reference are MIT; Inter/Newsreader retain SIL OFL. Any chosen form provider has its own terms. rc.12 adds no contact transport, storage, credentials or library. [Validation](VALIDATION.md).
